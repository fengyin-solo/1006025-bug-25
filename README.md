# 机场地面保障作业管理平台

面向航班保障、机位分配、廊桥靠接、摆渡车调度、行李装卸、航油加注、除冰作业与延误处置的一体化机场地面保障作业工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `airport-ground-ops:entries` 这一项，或调用 `resetModule(模块)`。

## 航油加注：统一取数口径与月度用量报表

航油加注的三类源数据原本分散登记——作业主档（油品规格/航班日期/状态）、计量点读数（加注量）、
静电接地检查结果，旧版导出直接遍历计量读数，导致已完成漏读数的作业漏加、重复读数重复计费、
接地检查并不进来，且与页面合计各算各的。现在统一收敛在 `frontend/src/data/fueling/`：

- `types.ts`：领域模型（作业主档/计量读数/接地检查/对账后的统一行）；
- `reconcile.ts`：三源对账与**唯一统计口径**。月份归属一律取作业主档的**航班日期**（计量日期只留档）；
  同一作业编号的读数去重保留一条；计量点油品规格与主档不一致时对齐主档；
  已完成缺读数按 0 升纳入并挂告警、缺接地检查显示「未记录」；孤立读数/检查留档但不进统计；
- `store.ts`：独立持久化键 `airport-ground-ops:fueling`，「迁移→对账→落库」与读取在同一步完成，
  页面表格、页面月度合计、月度报表导出、运营概览以及任何通用入口（`local-service.ts` 对 fueling
  做了适配）读的都是同一份对账结果；状态流转改主档后立即重新对账落库；
- `exporter.ts`：月度用量报表管线，分 `collect`（取数）/`write`（逐行生成）/`deliver`（产出文件）
  三阶段。只有内容完整生成后才触发浏览器下载，失败不会留下空文件；失败信息带阶段名与中断行；
  write 阶段逐行落检查点（`airport-ground-ops:fueling-export-checkpoint`），重试从中断的下一条继续；
  重试前逐行比对字段指纹，源数据已变则旧半成品作废、整单重跑，文件里不会出现旧值行。

**存量数据口径结论：按新口径重算，不按当时口径留档。** 月度用量是运营考核与对账依据，旧口径本身
存在漏加、重复计费、跨月错配三类错误，按旧口径留档会让错误金额继续流转。重算只做数据归位（去重、
规格对齐、按航班日期回填月份、漏行补零并挂告警），不虚构加注量；每一笔修正都写入对账日志并在页面
展示，修正幂等、可追溯。源数据（原始计量日期、原始规格值的修正记录）保留在数据集中留痕。
